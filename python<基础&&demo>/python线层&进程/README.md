## 学习总结

### 线程适合什么任务

线程共享同一进程的内存空间，创建和切换成本较低，适合等待时间较多的 I/O 任务，例如网络请求、文件读写和数据库访问。这里用 `time.sleep()` 模拟 I/O 等待：串行版本约需 8 秒，而多线程可以让等待时间重叠。

### 为什么需要锁

多个线程同时访问可变共享数据时，单独的“读取 → 计算 → 写回”不是一个整体。示例 03 在读取 `completed_count` 后主动等待，容易让多个线程读取到相同旧值，最终计数小于预期。示例 04 只给更新计数器的临界区加 `Lock`，保证一次只有一个线程更新它。

> 锁应尽量短小，只保护共享状态的读写；不要在锁内执行网络请求或长时间休眠。

### 线程池和队列的分工

- **线程池**：任务形式统一、数量已知时很方便；`map` 会按输入顺序收集结果。
- **任务队列**：更适合生产者持续投递任务、消费者并发处理的模型。每次 `get()` 后都必须对应一次 `task_done()`；用 `None` 作为哨兵，让每个工作线程退出。

### 线程与进程的选择

| 对比项 | 线程 | 进程 |
| --- | --- | --- |
| 内存 | 同一进程内共享 | 各自独立 |
| 适合任务 | I/O 密集型 | CPU 密集型 |
| 通信 | 共享变量，但要同步 | 队列、管道等 IPC |
| 代价 | 较低 | 创建和传递数据的代价较高 |

Python 的 GIL 会限制多个线程同时执行 Python 字节码，因此纯计算任务通常更适合 `multiprocessing` 或 `ProcessPoolExecutor`。多进程入口也应放在 `if __name__ == "__main__":` 下，避免子进程重复执行模块顶层代码。
